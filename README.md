# vibe-coding-workflow

一个人 + AI 协作做产品的标准工作流。核心理念：**人管体验，AI 管执行；先定义"完成"再动手；所有"手感"类目标参数化对齐。**

这不是理论整理。全部条目来自一个真实项目（护肤空瓶记录小程序）两个月的踩坑复盘：哪些承诺没兑现、哪些行为在改版里静默丢失、哪些"应该没关系"最后变成误判。每一条都能对应到一次返工。

## 适合谁

- 不写（或只写一点）代码，但想独立把产品做出来的人
- 用 AI 编程工具时反复遇到"做出来了但不是我要的"的人
- 需要和 AI 建立可审查协作契约的人

## 内容

- [SKILL.md](SKILL.md)：阶段 0-6 的完整清单（立项、需求、规格与完成标准、设计、开发、验收、交接），外加一节"反例信号"——看到哪些念头就该停下来。
- [assets/mockup-template.html](assets/mockup-template.html)：帧式视觉稿模板，自带调参面板（视觉参数 + 行为参数），人调满意后导出参数 JSON 作为实现契约。复制到你项目里，把设计令牌换成你自己的风格再用，模板默认值是中性占位符。

## 怎么用

1. 新项目开工前，过一遍阶段 0 的四件事：git 基线、环境清单、工具降级预案、被砍清单。这四件事是后面所有环节不被单点事故摧毁的前提。
2. 把 SKILL.md 直接投喂给你的 AI 编程助手（它是 QoderWork / 千问办公的 Agent Skill 格式，也可当纯 Markdown 清单用），让它按阶段推进，每个阶段等你确认再走下一步。
3. 做视觉稿时用模板出帧，动效承诺必须单独登记为行为规格——静态帧承载不了行为。

## 一句话版本

> 把"我感觉不对"翻译成"参数表第几行不对"，把"应该做完了"翻译成"验收方案第几条过了"。
